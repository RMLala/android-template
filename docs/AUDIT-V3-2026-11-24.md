## Écarts prouvés par domaine

### 1. Page À propos & Support et historique des versions

- **AppForge Studio** : la page À propos & Support existe et comprend les informations de support, guide/FAQ, diagnostic avec consentement et informations de confidentialité. Aucun historique de versions de l'application n'y est identifié ; le contrôle `promptHistory` trouvé dans le HTML concerne l'historique des prompts/projets, pas les versions de l'application. En revanche, le HTML Android sur `main` fixe le titre à **15.8.2**, alors que Gradle et les artefacts de build sont en **15.8.8**. Écart de version d'interface prouvé.
- **WorshipFlow** : la PR #12 a aligné `VER` sur 5.8.8. La chaîne `CHG` affiche toutefois encore une note formulée comme version 5.8.6 ; vérifier si elle est exposée dans l'écran About et l'actualiser si nécessaire.
- **WorshipFlow** : l'About ne reflète pas le statut réel de licence/Cloud selon le dernier audit source du 23/11.
- **Autres applications** : ne pas conclure à l'absence d'historique sur simple présence de fichiers CHANGELOG ; seul l'historique affiché dans la page À propos est interdit par le standard.

### 2. AppForge Studio et Business Manager

Sur `main`, le test `tests/ultimate-business-integration.test.cjs` exige encore `ultimate-business-frame` et `srcdoc` : Business Manager reste monté dans une iframe. Le module séparé `modules/business-manager/index.html` présente un verrou PIN autonome à 4 chiffres. Il indique explicitement : « Chiffrement des exports : non disponible dans cette version ». Le code source de la page Studio affiche toujours le titre 15.8.2, contre 15.8.8 dans Gradle.

La page Studio de sauvegarde native Android utilise le sélecteur/partage natif sans OAuth intégré et propose AES-GCM/PBKDF2 facultatif. Cela ne chiffre pas l'export manuel JSON Business Manager.

La PR #42 (13 fichiers modifiés, changements de migration et d'intégration, 142 commits annoncés par GitHub) porte la consolidation du module, la migration des données et les actions Business Manager. Elle reste ouverte. #44 est seulement dans sa branche. **Ne pas fusionner #42 sans recette de migration, navigation, sauvegarde/restauration et vérification des données historiques.** La PR #42 est antérieure à la correction CI #45 ; son workflow doit reprendre la protection des secrets avant toute fusion.

Un dépôt séparé [appforge-business-manager](https://github.com/RMLala/appforge-business-manager) existe toujours, avec son propre `index.html` et son workflow CI. Il reste un prototype/source distinct et ne prouve pas l'intégration finale dans l'unique application Studio.

### 3. Drive, OAuth et chiffrement

- **LifeOS** : le code utilise Google Identity/OAuth (`drive.appdata`). Le stockage local est chiffré, mais le flux Drive récupère la valeur déchiffrée et l'envoie comme JSON ; le chiffrement local ne protège donc pas la copie distante. Les PR de correction restent ouvertes et le manifeste/service worker PWA sont toujours sur `main`.
- **WorshipFlow** : la sauvegarde partagée reste un JSON sérialisé non chiffré selon le contrôle source précédent ; la PR #12 ne modifie pas ce parcours.
- **CPV Hebdo** : partage Android natif sans OAuth intégré ; AES-GCM est proposé en option. Le verrouillage reste facultatif.
- **Passkeep** : partage natif sans OAuth et sauvegarde du coffre chiffré. Le PIN est obligatoire ; la biométrie reste activable séparément et n'est pas démontrée prioritaire automatiquement.
- **AppForge Studio** : partage natif sans OAuth et chiffrement facultatif pour la sauvegarde Studio ; exception Business Manager : export JSON non chiffré.
- **Mada-courses** : sauvegarde JSON locale, sans preuve de chiffrement ni de partage Drive natif sur `main`.

### 4. Biométrie prioritaire et PIN

Le standard exige un PIN obligatoire, biométrie prioritaire si disponible et PIN en secours.

- **AppForge Studio** : le README décrit le verrou global comme facultatif et désactivé par défaut. Le plugin natif propose biométrie forte/identifiants Android, mais aucun PIN applicatif 4 chiffres de secours partagé n'est démontré. Le PIN Business Manager est indépendant.
- **WorshipFlow** : le code affiche « verrouillage facultatif et désactivé par défaut » et règle la biométrie séparément ; non conforme à l'obligation de verrouillage.
- **CPV Hebdo** : le réglage PIN est facultatif ; biométrie séparée. Non conforme à l'obligation de PIN.
- **Passkeep** : PIN obligatoire et biométrie disponible, mais activation biométrique explicite ; priorité automatique non démontrée.
- **Liberté** : README/tests déclarent biométrie prioritaire et PIN de secours ; cela reste une preuve statique, pas un test sur appareil physique.
